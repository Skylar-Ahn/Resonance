# TASK-ID 작업 제목

> 상태: Draft
> 담당: 미정
> 갱신일: YYYY-MM-DD
> 작업 종류: 문서 / 프로토타입 / 제품 구현 중 선택

## 목표와 근거

- 사용자 요청과 완료 시 달라지는 결과:
- 관련 Decision ID: [기존 결정 로그](../decisions/DECISION_LOG_AND_OPEN_QUESTIONS.md)의 해당 D/DR 번호와 상태
- 관련 UF ID: [User Flow](../product/USER_FLOW.md)의 해당 UF 번호
- 필수 입력: [인덱스](../00_README.md), [협업](../process/WORKFLOW_AND_AGENT_HANDOFF.md), [IA](../product/IA.md)의 관련 절과 선택한 분야 문서의 상대 링크

## 범위

- 포함:
- 제외:
- 시작 사용자 상태·데이터:
- 정확한 실행 경로: 시작 화면 → 행동 → 도착 상태
- 구현 후 실행 명령·URL: 검증한 실제 값 기록

## 의존성과 결정

| 항목 | 분류 | 현재 상태·근거 | 해제·교체 조건 |
| --- | --- | --- | --- |
| 작성 필요 | 제품 정책 / 기술 선택 / 자산 / 임시 선택 | 차단 / 후속 / 준비 완료 | 담당·관련 DR |

확정할 수 없는 제품 정책은 기존 로그에 Decision Request로 기록한다. 임시 선택은 별도 ID를 주고 적용 작업·수명·검증 방법을 명시한다. 프로토타입 선택을 제품 결정으로 승격하지 않는다.

## 수용 기준과 검증

| ID | Given / When / Then 또는 관찰 가능한 결과 | 검증 방법 | 결과 |
| --- | --- | --- | --- |
| AC-01 | 작성 필요 | 명령 또는 재현 단계 | 미실행 |

성공 경로와 관련 loading/empty/error/partial/unsupported 상태, 반응형·키보드 사용을 포함한다. 해당하지 않는 항목은 이유를 적는다.

## 실행 기록과 인계

- 변경 파일:
- 검증 명령·종료 결과:
- 미실행 검사와 이유:
- 남은 결정:
- 다음 실행의 첫 단계:
- 완료 판단: 수용 기준 충족 증거를 확인한 뒤 Done으로 전환
