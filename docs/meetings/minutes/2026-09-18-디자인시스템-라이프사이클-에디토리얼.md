# Resonance Discussion Note

> **Date:** 2026-09-18  
> **Topic:** 디자인 시스템의 lifecycle 중심 구조와 editorial visual direction  
> **Area:** Product / UX/UI  
> **Status:** Partially Decided  
> **Related:** `docs/product/IA.md`, `docs/product/USER_FLOW.md`, `docs/product/PRODUCT_SPEC.md`, `docs/design/DESIGN_SYSTEM.md`, `docs/design/INTERACTION.md`, `docs/design/REFERENCE_MAP.md`

## 1. Context

Resonance의 디자인 시스템을 컴포넌트 생성 전에 Discovery 단계에서 정리했다. 제품 철학은 공연을 발견하고, 기다리고, 준비하고, 경험하고, 회고하고, 기억하는 전체 lifecycle을 하나의 연속적인 경험으로 만드는 것이다. 기존 IA의 `For You / Articles / Reviews` 전역 메뉴는 유지하되, 화면 상태와 행동 우선순위를 페이지 종류가 아니라 공연의 시간·사용자 관계·현재 맥락에 따라 결정하는 방향을 검토했다.

동시에 App Home의 기존 LP/스타일러스 메타포를 liquid-glass 물방울과 노란 종이배, ripple interaction으로 대체하는 새 비주얼 방향과, 세 전역 탭의 첫 화면을 editorial하게 구성하는 방안을 검토했다.

## 3. Options Considered

### Option A — 정적 Editorial 중심

- 핵심: 내부 화면과 홈까지 프로그램북·브로셔·매거진 문법을 중심으로 통일한다.
- 장점: 정보 계층과 읽기 흐름이 명확하고 클래식 공연 맥락에 자연스럽다.
- 문제점: 제품 철학의 “경험의 시간성”과 음악 재생 interaction을 충분히 표현하지 못하고 정적으로 느껴질 수 있다.

### Option B — Ambient / Instrumental UI 중심

- 핵심: liquid glass, ripple, slow motion, spatial interaction을 앱 전반으로 확장한다.
- 장점: Resonance 고유의 감각적 identity를 만들기 쉽다.
- 문제점: 정보 탐색성과 접근성이 약해지고, 과용 시 럭셔리 캠페인·웰니스·컨셉 아트처럼 보일 수 있다.

### Option C — Kinetic / Resonant Editorial

- 핵심: 정보 구조는 Editorial하게 유지하고, 음악과 시간의 변화를 표현해야 하는 순간에만 ambient motion과 brand interaction을 사용한다.
- 장점: 프로그램북 같은 정보 명료성과 Resonance 고유의 감각적 경험을 함께 유지할 수 있다.
- 문제점: motion과 brand expression의 사용 범위를 명확히 제한하지 않으면 시각적 일관성이 깨질 수 있다.

## 4. Decisions

### Decided

- **D-01. 제품 철학의 중심은 공연 경험 전체 lifecycle이다.**
  - 이유: 공연 발견, 기다림, 준비, 경험, 회고, 기억을 독립 기능이 아니라 하나의 연속된 경험으로 연결하기 위해서다.
  - 영향 범위: Product, IA/User Flow 해석, Design System, Interaction, 추천/개인화의 장기 방향.

- **D-02. `For You / Articles / Reviews` 전역 내비게이션은 lifecycle 모델로 대체하지 않는다.**
  - 이유: 전역 메뉴는 사용자가 콘텐츠에 접근하는 관점이고, lifecycle은 같은 공연이 시간과 사용자 관계에 따라 어떤 상태와 행동을 가져야 하는지를 결정하는 별도 축이다.
  - 영향 범위: IA는 유지. UX state, component variation, CTA priority 설계에 lifecycle을 추가한다.

### Tentative

- **T-01. Lifecycle state는 단일 enum보다 `Temporal Phase + Engagement State`의 조합으로 설계하는 방향이 유력하다.**
  - 추가 검증 또는 결정이 필요한 내용: 실제 state 이름, 전환 조건, 저장 데이터와 UI state의 경계.

- **T-02. Design System 원칙으로 Continuity over Navigation, Time is Structure, Context before Action, Editorial not Feed, Memory Accumulates, Resonance with Restraint를 제안했다.**
  - 추가 검증 또는 결정이 필요한 내용: 최종 principle 명칭과 수, canonical 문서 반영 여부.

- **T-03. 시각 언어를 `Kinetic Editorial` 또는 `Resonant Editorial`로 정의하는 방향을 제안했다.**
  - 추가 검증 또는 결정이 필요한 내용: 명칭 확정 및 Home/내부 화면 간 구체적인 공통 규칙.

- **T-04. App Home은 Ambient/Experience mode, For You·Articles·Reviews·Concert Detail은 Editorial/Reading mode를 기본으로 하는 2-mode 구조를 제안했다.**
  - 추가 검증 또는 결정이 필요한 내용: mode 간 typography, spacing, surface, motion 공유 규칙.

- **T-05. App Home의 liquid-glass 물방울 + 노란 종이배 + ripple interaction은 Resonance의 brand metaphor로 유지 가치가 있다고 평가했다.**
  - 추가 검증 또는 결정이 필요한 내용: 실제 interaction affordance, 음악 재생 연동, reduced-motion 대체, 성능, 모바일 drag UX.
  - 주의: literal LP 시뮬레이션보다 water/resonance propagation metaphor로 독립시키는 방향을 제안했다.

- **T-06. 현재 홈의 graphite/olive/amber/ivory 계열은 제품 분위기와 잘 맞는 후보 palette로 평가했다.**
  - 추가 검증 또는 결정이 필요한 내용: 실제 primitive/semantic token 값, contrast, light/dark 대응.
  - 노란 종이배는 모든 CTA 색이 아니라 user intervention / resonance trigger를 나타내는 제한적 brand accent 후보로 제안했다.

- **T-07. For You는 날짜와 공연을 중심으로 한 `Temporal Editorial` 리스트 구조가 적합하다고 평가했다.**
  - 추가 검증 또는 결정이 필요한 내용: 카드 정보 밀도, 좌석 추천 summary의 prominence, bookmark 포함 여부.

- **T-08. Reviews는 순수 masonry/grid보다 `Archival Editorial`의 연대순 리스트 또는 하이브리드 구조가 적합하다고 평가했다.**
  - 추가 검증 또는 결정이 필요한 내용: 연도/공연장/작곡가 등의 검색·정렬·필터, 좌석 메타데이터 노출 수준.

- **T-09. Articles 첫 화면은 raw archive/list보다 `Reading Editorial`의 큐레이션 허브가 적합하다고 평가했다.**
  - 추가 검증 또는 결정이 필요한 내용: `For Your Next Concert`, Composer/Theme 구획, All Articles/Archive의 위치와 분류 체계.

- **T-10. liquid glass, ripple, paper boat, ambient background는 일반 UI primitive가 아니라 Design System의 Brand Expression layer로 분리하는 방향을 제안했다.**
  - 추가 검증 또는 결정이 필요한 내용: 어느 화면·상태에서 brand expression을 허용할지 명세.

## 5. Open Questions

- **Q-01.** 최신 App Home 목업에서 `For You`가 active로 표시되는데, canonical IA의 “App Home에서는 모든 전역 메뉴 비선택” 규칙을 유지할 것인가, 아니면 이 화면을 `For You`의 hero로 재분류할 것인가?
- **Q-02.** App Home의 음악 재생 interaction을 실제 제품 기능으로 확정할 것인가?
- **Q-03.** 음악 재생을 Apple Music과 연결할 경우 기술적·정책적 구현 범위는 어디까지인가?
- **Q-04.** Lifecycle의 temporal phase와 engagement state의 정확한 상태 목록과 전환 조건은 무엇인가?
- **Q-05.** 공연 시점에 따라 Concert Detail과 For You에서 어느 정보와 CTA의 prominence가 어떻게 변하는가?
- **Q-06.** 종이배 interaction의 drag affordance를 텍스트 설명 없이 어떻게 인지시키며, reduced motion·키보드·터치 접근성을 어떻게 제공할 것인가?
- **Q-07.** 홈의 ambient motion과 내부 editorial 화면 사이에서 반드시 공유해야 할 typography, grid, color, spacing, border 규칙은 무엇인가?
- **Q-08.** Articles 첫 화면의 최종 정보구조는 어떻게 구성할 것인가?
- **Q-09.** Reviews 첫 화면의 archive 탐색 단위와 정렬·필터는 무엇인가?
- **Q-10.** Lifecycle semantic token, primitive token, brand expression token의 실제 Figma Variable 구조와 naming을 어떻게 정의할 것인가?
