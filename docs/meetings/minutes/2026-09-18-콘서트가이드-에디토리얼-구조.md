# Resonance Discussion Note

> **Date:** 2026-09-18  
> **Topic:** Concert Guide 정보구조와 반응형 에디토리얼 규칙  
> **Area:** Product / UX/UI  
> **Status:** Partially Decided  
> **Related:** Articles IA, Article Detail, Responsive Rules, 향후 Editorial Spec

## 1. Context

여러 작곡가·작품·협연자가 포함될 수 있는 클래식 공연을 하나의 사전 감상 콘텐츠로 구성할 때, 모든 작품을 별도 아티클로 나열하거나 한 작곡가를 과도하게 깊게 다루는 구조가 적절한지 검토했다. 그 결과 Articles의 상위 정보구조와 Concert Guide 내부 모듈의 역할을 분리하고, 화면 크기와 공연별 콘텐츠 길이가 달라져도 읽기 순서와 정보 계층이 깨지지 않는 반응형 에디토리얼 원칙을 논의했다.

## 2. Key Discussion

| 구분 | 핵심 내용 |
| --- | --- |
| 고민한 문제 | 한 공연에 여러 작품이 있을 때의 글 분할 단위, Program Story의 필요성, Work Note와 Deep Dive의 경계, Articles 메인의 정보 계층, Compact~Extended Guide의 길이 변화, 모바일·태블릿·데스크톱의 에디토리얼 레이아웃 규칙을 검토했다. |
| User 제안 | 공연 전체 맥락을 먼저 파악해야 하며, 프로그램 자체에 깊은 기획 의도가 없는 공연도 많으므로 테마를 강제해서는 안 된다고 제안했다. Articles에서는 예매 티켓 연동보다 북마크 공연을 활용하거나, 아예 Concert Guides / Deep Dives 두 가지 정보구조로 한정하는 방향을 선호했다. Hero에서는 작품명을 반복하지 않고 작곡가명만 표시하는 것을 제안했다. 모바일 2-column은 금지하되 큰 화면에서는 에디토리얼 구성을 더 적극적으로 사용할 수 있다고 보았다. |
| ChatGPT 제안 | Articles의 최상위 콘텐츠 타입을 Concert Guides와 Deep Dives 두 가지로 두고, Work Note는 Concert Guide 내부 모듈로 한정했다. Concert Guide는 프로그램 순서를 기본 축으로 사용하고 Program Story, Artist Perspective, Special Note를 조건부 모듈로 삽입한다. Guide 길이는 Compact / Standard / Extended로 분류하되 동일한 Editorial Grammar를 확장하도록 제안했다. |
| 상호 피드백 | 공연에 의미 있는 프로그램 서사가 없으면 Program Story를 만들지 않는 방향으로 정리했다. Hero는 공연 정체성만 담당하고 작품 상세는 Before You Listen과 Program Map으로 넘겨 정보 중복을 줄였다. 태블릿·데스크톱에서는 긴 연속 본문을 신문식 다단으로 쪼개기보다 Narrative와 Supporting/Visual/Accent를 병치하는 방향으로 조정했다. |
| 제약·전제 | 콘텐츠 의미 순서와 출처 관계는 모든 디바이스에서 유지되어야 한다. 레이아웃은 반응형으로 달라질 수 있지만 AI가 픽셀 수준의 임의 배치를 결정하지 않는다. |

## 3. Options Considered

### Option A — Articles에 모든 작품별 아티클을 동일 위계로 나열

- 핵심: 작품마다 독립 아티클을 생성하고 Articles 목록에서 순서대로 노출한다.
- 장점: 구조가 단순하고 개별 작품 탐색이 쉽다.
- 문제점: 한 공연에 작품이 많을수록 아티클이 과도하게 늘고, 사용자가 '오늘 공연을 어떻게 들을지'라는 맥락을 잃기 쉽다.

### Option B — Concert Guide + Deep Dive

- 핵심: 공연별 사전 감상 패키지는 Concert Guide로 묶고, 작품별 핵심 설명은 내부 Work Note로 제공한다. 더 깊은 주제만 독립 Deep Dive로 분리한다.
- 장점: 공연 맥락을 보존하면서 정보량을 조절하고 Deep Dive를 여러 공연에서 재사용할 수 있다.
- 문제점: Work Note와 Deep Dive 승격 기준, Guide 길이별 편집 규칙이 필요하다.

### Option C — 티켓 구매 정보를 기반으로 Guide 개인화

- 핵심: 사용자가 실제 예매한 공연만 Concert Guide에 우선 노출한다.
- 장점: 공연 준비 경험과 직접 연결된다.
- 문제점: 예매처 연동, 구매 확인, 취소·변경 동기화, 개인정보 처리 등 핵심 범위를 크게 벗어나는 백엔드 복잡도가 추가된다.

## 4. Decisions

### Decided

- **D-01. Articles의 최상위 콘텐츠 유형은 `Concert Guides`와 `Deep Dives` 두 가지로 한정한다.**
  - 이유: 사용자에게 보이는 정보구조를 단순하게 유지하면서 공연 중심 콘텐츠와 독립 심층 콘텐츠의 역할을 분리하기 위해서다.
  - 영향 범위: Articles IA, Articles 목록 화면, 콘텐츠 모델.

- **D-02. Concert Guide는 특정 공연에 종속된 사전 감상 에디토리얼 패키지다.**
  - 이유: 여러 작품·작곡가·연주자 정보를 공연이라는 하나의 맥락 안에서 읽게 하기 위해서다.
  - 영향 범위: Concert Detail > Articles, Article Detail, Articles 메인.

- **D-03. Work Note는 독립 Article이 아니라 Concert Guide 내부의 작품별 핵심 감상 모듈이다.**
  - 이유: 작품 수만큼 아티클이 증가하는 것을 막고, 실제 공연 순서를 따라 자연스럽게 읽게 하기 위해서다.
  - 영향 범위: Concert Guide 구성, 콘텐츠 데이터 모델.

- **D-04. Deep Dive는 한 가지 질문·주제·현상을 깊게 다루는 독립 에디토리얼이며 여러 공연에서 재사용 가능해야 한다.**
  - 이유: Work Note의 핵심 정보와 장문의 음악학적·역사적 탐구를 분리하기 위해서다.
  - 영향 범위: Deep Dive 목록, 관련 공연/작품 연결.

- **D-05. Program Story, Artist Perspective, Special Note는 조건부 모듈로 두고 근거나 필요가 없으면 섹션 자체를 표시하지 않는다.**
  - 이유: 빈 슬롯을 채우기 위한 AI 과잉생성을 방지하고 공연마다 다른 맥락을 자연스럽게 수용하기 위해서다.
  - 영향 범위: Concert Guide 생성·렌더링 규칙.

- **D-06. 프로그램 전체의 특별한 테마가 확인되지 않는 공연은 실제 공연 순서를 Concert Guide의 기본 구조로 사용한다.**
  - 이유: 기획 의도를 추측하지 않고도 사용자의 실제 공연 경험 순서와 읽기 순서를 일치시킬 수 있다.
  - 영향 범위: Program Map, Work Note 순서.

- **D-07. Hero는 공연의 정체성만 전달하고 대표 프로그램 작품을 일일이 나열하지 않는다. 작곡가명은 사용할 수 있다.**
  - 이유: Hero, Before You Listen, Program Map 사이의 반복을 줄이고 각 섹션의 역할을 분명히 하기 위해서다.
  - 영향 범위: Concert Guide Hero 디자인.

- **D-08. 모바일에서는 Strict single-column을 사용하고 연속된 장문 Narrative를 2-column으로 배치하지 않는다.**
  - 이유: 작은 화면에서 읽기 순서와 가독성을 안정적으로 유지하기 위해서다.
  - 영향 범위: Responsive Editorial Rules.

- **D-09. Guide 길이가 달라도 별도 템플릿을 남발하지 않고 동일한 Editorial Grammar를 확장한다.**
  - 이유: Compact / Standard / Extended Guide 사이의 제품 일관성을 유지하면서 공연별 정보량 차이를 수용하기 위해서다.
  - 영향 범위: Editorial Spec, 렌더링 규칙.

- **D-10. 티켓 구매 여부를 Articles IA의 전제로 삼지 않는다.**
  - 이유: 외부 예매처 연동과 구매 확인은 현재 Articles 핵심 목적에 비해 백엔드 복잡도가 크다.
  - 영향 범위: Articles 개인화, MVP 범위.

### Tentative

- **T-01. 사용자가 저장/북마크한 공연의 Concert Guide를 Articles에서 우선 노출하는 방향을 사용한다.**
  - 추가 검증 또는 결정이 필요한 내용: 북마크 기능의 MVP 포함 여부와 정렬·우선 노출 UI.

- **T-02. Work Note는 Compact / Standard / Feature 수준으로 정보 밀도를 조정한다.**
  - 추가 검증 또는 결정이 필요한 내용: 실제 분량 기준, Feature 판정 기준, 작품 수가 많은 공연의 grouping 규칙.

- **T-03. Guide 전체는 Compact / Standard / Extended로 구분하고 Extended에서는 내부 section index / TOC를 제공한다.**
  - 추가 검증 또는 결정이 필요한 내용: 전환 기준과 모바일 TOC 표현 방식.

- **T-04. 태블릿 Portrait에서는 하나의 reading column을 유지하되 Narrative + Aside, Image + Context, Quote + Context 등 역할이 다른 모듈의 2-column 병치를 허용한다.**
  - 추가 검증 또는 결정이 필요한 내용: 실제 세로 태블릿 폭에서의 가독성 검증.

- **T-05. 태블릿 Landscape와 Desktop에서는 비대칭 배치, main/aside, image/text juxtaposition, 큰 타이포그래피 등 보다 적극적인 editorial grid를 사용한다.**
  - 추가 검증 또는 결정이 필요한 내용: breakpoint, 최대 본문 폭, grid column 수, 레이아웃 variant 수.
