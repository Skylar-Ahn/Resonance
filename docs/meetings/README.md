# Resonance Meetings

이 디렉터리는 ChatGPT와 사용자가 Resonance를 설계·검토하면서 진행한 논의의 핵심을 짧게 보존한다.

회의록은 **논의 과정과 판단 근거를 보존하는 기록물**이다. 현재 구현 기준을 직접 정의하는 canonical specification이 아니다. 확정된 결정이 제품 구조나 구현 기준을 바꾸면 관련 `docs/decisions/`, IA, User Flow, Product Spec 또는 분야별 상세 문서를 별도로 갱신해야 한다.

## 작성 트리거

사용자가 Resonance 프로젝트 대화에서 메시지에 `#회의록`을 포함하면 현재 대화의 관련 논의를 회의록으로 정리한다.

기본 동작:

1. 현재 대화에서 실질적인 제품·디자인·기술 논점을 추출한다.
2. 고민한 문제, User 제안, ChatGPT 제안, 상호 피드백을 핵심만 남긴다.
3. `Decided`, `Tentative`, `Open Questions`를 명확히 분리한다.
4. 결정되지 않은 사항을 임의로 확정하지 않는다.
5. 관련 문서와 후속 반영 대상을 식별한다.
6. 필요할 때만 표, Mermaid 다이어그램 또는 이미지를 사용한다.
7. `TEMPLATE.md` 형식으로 Markdown 파일을 작성해 이 디렉터리에 저장한다.
8. GitHub 저장소 `Skylar-Ahn/Resonance`의 기본 브랜치에 반영한다.

## 파일명 규칙

```text
YYYY-MM-DD-회의주제.md
```

예:

```text
2026-09-18-회의록-운영규칙.md
2026-09-18-좌석추천-시각화.md
2026-09-18-ai개발-워크플로우.md
```

회의 주제는 파일명만 보고도 무엇을 결정하거나 검토했는지 알 수 있도록 짧고 구체적으로 작성한다.

같은 날짜에 여러 논의가 있으면 각각 별도 파일로 분리한다. 동일 주제의 같은 논의를 이어서 정리하는 경우 기존 파일을 갱신할 수 있다.

## 작성 원칙

- 전체 대화를 그대로 요약하지 않는다.
- 잡담, 반복 피드백, 단순 문답은 최종 판단에 필요하지 않으면 제외한다.
- 무엇을 왜 검토했고, 어떤 피드백으로 결정이 바뀌었는지 복원 가능할 정도만 남긴다.
- User와 ChatGPT의 제안 출처는 향후 판단에 의미가 있을 때 구분한다.
- 확정된 내용과 잠정안, 제안, 가설, Open Question을 섞지 않는다.
- 기존 문서와 충돌하면 회의록에서 충돌을 명시하고 canonical 문서를 자동으로 덮어쓰지 않는다.
- 한 회의록은 가능하면 하나의 중심 주제를 다룬다. 독립적인 논점이 여러 개면 파일을 분리한다.
- 표와 Mermaid는 정보 구조를 더 짧고 명확하게 만들 때만 사용한다.
- 이미지는 UI 전후 비교나 구조 판단의 근거가 되는 경우에만 사용한다.
